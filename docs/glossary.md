# Glossary

Terms used in AI agent and retrieval-augmented generation (RAG) engineering. Each entry states
the problem the term solves, how it solves it, and where it appears in campus-rag.

**Status values**

- **Implemented**: built; the link points to code and, where relevant, measured results.
- **Background**: defined for context; not part of this project.

When a change implements a term, update its row: link to the code or results and set the status
to **Implemented**.

## Retrieval and grounding

| Term | Problem it solves | How it solves it | In campus-rag | Status |
|------|-------------------|------------------|---------------|--------|
| **RAG** (retrieval-augmented generation) | An LLM knows only its training data, so it cannot answer about private, recent, or niche documents, and it guesses when it doesn't know. | Retrieves relevant passages at question time and places them in the prompt, so the model answers from current evidence without retraining. | The whole service: hybrid retrieval ([`retrieve/`](../src/campus_rag/retrieve/)) feeds grounded generation ([`generate/`](../src/campus_rag/generate/)), run end to end by [`AnswerService.answer`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/generate/answer.py#L45-L107); see [architecture](architecture.md). | Implemented |
| **Grounding** (contextual grounding) | Readers cannot tell whether a model's answer is true or invented. | Instructs the model to answer only from supplied passages and to cite them, so every claim can be checked against a source. | Cited answers; unsupported questions are declined: [`SYSTEM_PROMPT`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/generate/prompt.py#L14-L23), [`check_answer`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/generate/citations.py#L31-L37). [Generation](architecture.md#generation) | Implemented |
| **Research corpus grounding** | General-purpose answers ignore the specific, authoritative documents an organization relies on. | Restricts retrieval to a curated collection, so answers reflect that collection rather than the open web. | Answers come only from the allowlisted UW corpus: the [`uw-policy` source](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/config/sources.toml#L4-L15). [Data sources](data-sources.md) | Implemented |
| **Corpus** | A system needs a defined body of knowledge to search. | Collects the documents in scope into one indexed collection. | 247 UW Policy Directory documents selected by [`config/sources.toml`](../config/sources.toml) rules through [`select_urls`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/ingest/sources.py#L127-L159) and loaded by [corpus ingestion](../runbooks/ingest-corpus.md). [Data sources](data-sources.md) | Implemented |
| **Chunking** | Whole documents are too long to fit many in a prompt, and one long vector blurs many topics together. | Splits documents into focused passages, often with overlap so ideas spanning a boundary survive, and retrieves passages instead of documents. | Heading-aware chunks with a heading-path prefix, overlap on split sections, and short-section merging: [`chunk_document`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/ingest/chunk.py#L38-L79). [Ingestion](architecture.md#ingestion) | Implemented |
| **Embedding** | Computers cannot compare meaning directly, and keyword matching misses paraphrases ("forgot my login" versus "reset password"). | A model converts text into a vector of numbers where similar meanings land close together, so meaning becomes measurable distance. | Chunks are embedded locally with `nomic-embed-text` by [`OpenAICompatibleEmbedder`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/index/embed.py#L35-L169); the same client embeds questions. [Index](architecture.md#index) | Implemented |
| **Embedding strategy** | A poor model choice or poorly framed text produces vectors that retrieve the wrong passages. | Deliberately chooses the model, the exact text embedded (for example, chunk plus its heading), and dimensions, then validates the choice with retrieval metrics. | Configurable model, dimensions, and task prefixes (`search_document: ` for chunks, `search_query: ` for questions) in [`EmbeddingSettings`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/config.py#L12-L23), applied by [`embed_documents`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/index/embed.py#L80-L86) and [`embed_query`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/index/embed.py#L88-L89); each chunk is embedded with its heading path. The [`campus_rag.evaluate embeddings`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/evaluate/__main__.py#L34-L38) command compares the [`VARIANTS`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/evaluate/embeddings.py#L139-L162) (no heading, no task prefixes, `bge-m3`, 256 dimensions) on the golden set: only removing the task prefixes lowers vector recall@1 by more than noise ([embedding strategy results](results/embedding-strategies.md)). | Implemented |
| **Vector search** (semantic search) | Finding passages that mean the same thing as a question even when they share no words. | Embeds the question and returns the stored vectors closest to it. | pgvector cosine-distance search: [`vector_search`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/retrieve/vector.py#L39-L65). [Retrieval](architecture.md#retrieval) | Implemented |
| **Cosine similarity** | Vector length varies with text length, which distorts raw distance comparisons. | Compares only the angle between vectors, so direction (meaning) matters and length does not. | The HNSW index uses `vector_cosine_ops` ([migration `003`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/index/migrations/003_embeddings_and_keyword_index.sql#L25-L29)); [`vector_search`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/retrieve/vector.py#L39-L65) orders by the [`<=>` cosine-distance expression](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/retrieve/vector.py#L60). | Implemented |
| **ANN** (approximate nearest neighbor) | Comparing a query against every stored vector is too slow at scale. | Builds an index that finds near-best matches by checking a small fraction of vectors, trading a little accuracy for large speed gains. | HNSW index on `chunk_embeddings` ([migration `003`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/index/migrations/003_embeddings_and_keyword_index.sql#L25-L29)). | Implemented |
| **HNSW** (Hierarchical Navigable Small World) | Needs an ANN index that is both fast and accurate. | Builds layered graphs of neighboring vectors; search starts in a sparse top layer and descends to dense layers, homing in on the closest matches. | Partial pgvector HNSW index for `nomic-embed-text` (`m = 16`, `ef_construction = 64`) in [migration `003`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/index/migrations/003_embeddings_and_keyword_index.sql#L25-L29). [Index](architecture.md#index) | Implemented |
| **Vector search optimization** | Default settings can be slow or miss relevant results. | Tunes index parameters, candidate counts, and filters while measuring recall and latency. | HNSW `ef_search` and iterative scanning in [`vector_search`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/retrieve/vector.py#L39-L65), with [`exact_vector_search`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/retrieve/vector.py#L68-L87) as the recall baseline: [HNSW recall](results/retrieval.md#hnsw-recall). | Implemented |
| **Vector database** | Applications need to store vectors with their text and metadata and query them quickly. | Combines vector storage, ANN indexes, and metadata filtering behind one query interface. | PostgreSQL with pgvector: the `chunk_embeddings` table stores vectors next to chunks and documents ([migration `003`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/index/migrations/003_embeddings_and_keyword_index.sql#L14-L23)). [Index](architecture.md#index) | Implemented |
| **pgvector** | Running a separate vector database adds another system to operate and keep in sync. | Adds vector columns and ANN indexes to PostgreSQL, so vectors, text, metadata, and SQL filters live in one database. | The project's vector store: the [`db` service in `compose.yaml`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/compose.yaml#L6-L21) runs PostgreSQL with pgvector; [`001_enable_pgvector.sql`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/index/migrations/001_enable_pgvector.sql#L1) enables it. | Implemented |
| **Pinecone** | Operating vector infrastructure at large scale takes effort. | Provides a fully managed, cloud-hosted vector database. | Alternative to pgvector. | Background |
| **Weaviate** | Teams want vector and keyword search in one self-hostable system. | Provides an open-source vector database with built-in hybrid search and modules. | Alternative to pgvector. | Background |
| **ChromaDB** | Prototypes need vector search without standing up a server. | Provides a lightweight vector database that can run inside a Python process. | Alternative to pgvector. | Background |
| **Keyword search** (full-text search, FTS) | Semantic search can miss exact identifiers such as policy numbers, system names, and acronyms. | Indexes the words in each document and matches query terms exactly, after normalizing word forms. | Generated [`search_tsv` column](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/index/migrations/003_embeddings_and_keyword_index.sql#L34-L47) with a [GIN index](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/index/migrations/003_embeddings_and_keyword_index.sql#L49) (migration `003`); [`keyword_search`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/retrieve/keyword.py#L100-L131) matches the question's stemmed words with OR and ranks with BM25. [Retrieval](architecture.md#retrieval) | Implemented |
| **TF-IDF** (term frequency-inverse document frequency) | Plain keyword matching overweights common words like "the" or "policy". | Scores a word higher when it is frequent in a document but rare across the corpus. | Keyword ranking uses BM25 ([`_BM25_SQL`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/retrieve/keyword.py#L46-L83)), which adds corpus-wide word rarity and chunk-length normalization that PostgreSQL's `ts_rank_cd` lacks: [keyword ranking results](results/retrieval.md#keyword-ranking). | Implemented (BM25, a TF-IDF refinement) |
| **BM25** (Best Matching 25) | TF-IDF overrewards repeated words and long documents. | Caps the benefit of repeated terms and normalizes for document length. | Keyword ranking, computed in SQL over `search_tsv` ([`_BM25_SQL`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/retrieve/keyword.py#L46-L83)). Replacing `ts_rank_cd` raised keyword recall@5 from 0.39 to 0.81. [Results](results/retrieval.md) | Implemented |
| **Hybrid retrieval** | Keyword search misses paraphrases; vector search misses exact terms. | Runs both searches and merges the results, so each covers the other's blind spots. | Keyword + vector search fused with RRF in [`PolicySearcher.search`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/retrieve/search.py#L64-L68). [Retrieval](architecture.md#retrieval) | Implemented |
| **RRF** (reciprocal rank fusion) | Keyword and vector scores use different scales, so they cannot be added directly. | Ignores raw scores and sums 1 / (k + rank) across result lists, rewarding passages ranked well by either method. | Fusion step in hybrid retrieval: [`reciprocal_rank_fusion`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/retrieve/fusion.py#L9-L55), `k = 60`. | Implemented |
| **Reranking** (cross-encoder) | Fast first-stage retrieval ranks candidates imprecisely. | Rescores a short candidate list with a slower model that reads the question and passage together. | Left out of the MVP: no local cross-encoder runs without PyTorch, and LLM reranking costs about 40 seconds per query on this CPU ([decision 11b](plans/mvp-design.md#11b-search)). Hybrid search already reaches recall@5 of 1.00. | Background |
| **Metadata filtering** | Relevant-sounding passages may come from the wrong source, section, or date. | Restricts search by structured attributes before or during ranking. | Filters by source and URL prefix in keyword and vector search ([`filter_conditions`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/retrieve/sql.py#L15-L32)); section filters are not built. | Implemented (source, URL prefix) |
| **Query rewriting** | Follow-up questions such as "what about for grad students?" lack the context needed for search. | Uses the LLM to rewrite the question into a standalone query using the conversation history. | First retrieval step for follow-up questions: [`rewrite_query`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/generate/rewrite.py#L54-L77). | Implemented |
| **Token** | Models and costs are limited by text length, but characters and words are inconsistent units. | Splits text into the subword units a model actually processes, giving a consistent measure. | Chunk sizes are measured in `cl100k_base` tokens ([`count_tokens`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/ingest/chunk.py#L33-L35)); the prompt's passage budget uses the same count in [`select_passages`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/generate/prompt.py#L60-L85). | Implemented |
| **Context window** | A model can consider only a limited amount of text per request. | Defines that limit in tokens, which every prompt must fit within. | Prompt assembly fits passages within a 3,000-token budget ([`PASSAGE_TOKEN_BUDGET`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/generate/prompt.py#L11)): [`select_passages`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/generate/prompt.py#L60-L85). | Implemented |
| **Context window management** | Overfilled prompts cost more, run slower, and bury relevant facts where models attend to them poorly. | Selects, orders, and compresses content so the most relevant evidence fits and stands out. | Up to six top passages, ordered by relevance, within a budget: [`build_prompt`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/generate/prompt.py#L33-L57) and [`select_passages`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/generate/prompt.py#L60-L85). [Generation](architecture.md#generation) | Implemented |
| **Long-context reasoning** | Some tasks need a model to consider very large inputs at once. | Uses models with very large context windows to reason over entire documents. | Selective retrieval is used instead. | Background |
| **Structured data augmentation** | Plain text passages lose attributes such as titles, sections, and URLs that answers and citations need. | Adds structured fields to the prompt alongside the text. | Passages carry their heading path and URL, which citations report: [`render_passage`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/generate/prompt.py#L88-L93). | Implemented |

## LLMs and agents

| Term | Problem it solves | How it solves it | In campus-rag | Status |
|------|-------------------|------------------|---------------|--------|
| **LLM** (large language model) | Software traditionally cannot understand or write flexible natural language. | Learns language patterns from large text corpora and generates text that follows instructions. | `qwen2.5:7b-instruct` writes grounded answers and `qwen2.5:3b-instruct` rewrites queries: [`ChatSettings`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/config.py#L26-L39) names the models and [`OpenAICompatibleChat`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/generate/chat.py#L47-L204) calls them. | Implemented |

| **Hallucination** | Models state unsupported claims confidently, which misleads readers. | Is reduced by grounding, citations, refusal rules, and evaluation that measures unsupported claims. | Reduced by citation checks: [`check_answer`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/generate/citations.py#L31-L37). | **Citation** | Readers cannot verify an answer without knowing its source. | Links each claim to the passage that supports it. | Answers cite passage numbers; citations to passages not supplied are removed, and an answer with none left is refused: [`check_answer`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/generate/citations.py#L31-L37), [`normalize_citations`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/generate/citations.py#L40-L64). | Implemented |
| **Chatbot** (conversational AI) | Users want to ask natural questions and follow-ups instead of searching. | Maintains conversation history and responds turn by turn. | `--chat` ([`_chat_loop`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/ask.py#L162-L179)) keeps the conversation and rewrites follow-ups: [ask questions](../runbooks/ask-questions.md). | Implemented |
| **AI agent** | Fixed pipelines cannot adapt when a task needs different steps or tools. | Lets an LLM choose actions and tools in a loop until it reaches a goal. | Agents call campus-rag `search_policies` as a tool ([`search_policies`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/mcp_server.py#L93-L157)). | Implemented |
| **Tool use** (function calling) | Models cannot act on systems or fetch live data by generating text alone. | The model emits a structured request; code executes it and returns the result. | The MCP [`search_policies`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/mcp_server.py#L93-L157) and [`draft_ticket`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/mcp_server.py#L159-L208) tools. | Implemented |
| **Agentic RAG** | Fixed retrieve-then-answer pipelines retrieve even when unnecessary and cannot search again when the first results are weak. | Gives retrieval to an agent as a tool, so it decides when to search, what to search for, and whether to search again. | MCP [`search_policies`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/mcp_server.py#L93-L157) tool. | **MCP** (Model Context Protocol) | Every AI application needs custom integration code for every tool or data source. | Defines a standard protocol, so a tool built once works with any MCP-compatible AI application. | MCP server exposing `search_policies` and `draft_ticket`: [`build_server`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/mcp_server.py#L85-L210). | Implemented |

| **Alignment** | Models can pursue instructions in ways that conflict with intended goals or values. | Trains and constrains models to behave helpfully, honestly, and safely. | Not used. | Background |
| **Intelligent automation** (AI-powered workflow automation) | Staff spend time on repetitive process steps that require reading and judgment. | Combines AI with workflow tools so routine steps run automatically, with people handling exceptions. | Unanswerable questions become drafted help-desk tickets: a refused answer carries a ticket draft ([`_ticket_draft`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/api/app.py#L273-L291)), and an agent files it with the MCP [`draft_ticket`](https://github.com/eocrawford/campus-rag/blob/0bc8b29d9829fe501e03785e2881de21ecc64c63/src/campus_rag/mcp_server.py#L159-L208) tool after the user agrees.
